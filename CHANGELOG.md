# Changelog

## Unreleased
- Shell: **Upgrade** is on the screen, so the whole path (sign in, choose, report, plan, prepare, upgrade) can be walked without leaving it. It shares everything that keeps Prepare safe: the plan is read first (nothing changed), the approval lists every firewall, the order, the outage and failover counts and every caution, nothing starts until APPROVE is typed, the approval is bound to that plan and written next to the journal, a plan older than 30 minutes cannot be approved, and quitting mid-run asks twice. Upgrade adds: a choice between continuing an unfinished earlier run of the same plan and starting a new one (the screen never prompts at the keyboard), a switch to include standalone firewalls (off), and **Stop after the steps in progress**, which stops the run from starting anything new.
- Behind it, `upgrade` is now two phases in `cli` (`_upgrade_review`, `_upgrade_execute`) the command and the screen share; the journal choice takes `tty=False` from the screen so it raises instead of asking. `Prepare` and `Upgrade` screens are subclasses of one `ChangeScreen`.
- Shell, jobs: the right-hand pane shows the last five lines of the newest job's log, and of every job still running, instead of one line; older finished jobs get one line. Each job now keeps a time-stamped log of its progress notes (up to 5000), and the Jobs screen lets you Tab (or Right) into the selected job's log and scroll all of it (Up, Down, PgUp, PgDn, Home, End); a running job's log follows its end until you scroll up.
- `report` now says which firewalls lag behind Panorama (the same single "PAN-OS version lagging behind Panorama" note the plan gives, using `spread_limit` and `panorama_compare`), so it no longer has to wait for the plan. `report` takes `--settings`, `--set` and `--releases` for this, and its JSON output has an `advice` list.
- Plan steps: an active member of a pair gets a new step "wait for the passive firewall's upgrade to finish" before "fail over", and the fail-over note now says its already upgraded passive peer takes over. The step is a real checkpoint: it confirms the passive peer is on the version this member is going to, and refuses to hand over to one that is not. In the step listing every firewall is shown with the role it has now, e.g. "e2 (currently active)", "d2 (currently passive)".
- The "PAN-OS version lagging behind Panorama" advice is said once: one note naming every firewall that is more than the limit behind (serial, hostname, PAN-OS version, in columns), with the explanation given a single time, instead of the same sentence repeated for every firewall (and again for the fleet). The per-firewall lines for it are gone from the plan's firewall blocks (`--verbose` still shows them). If the target would itself still be out of range, that is added to the same note. JSON plans carry it as one advice item (`code: version_lagging`, with a `devices` list); the console plan, the text report and the lines `prepare` prints all use it.
- Shell: **Prepare** is on the screen. It reads the plan (nothing changed), lists exactly what is being approved, and starts only when APPROVE is typed; the approval is bound to that plan's hash and written next to the journal, as on the command line. A plan older than 30 minutes, or for a different address or target, cannot be approved. The run shows live progress, keeps going if you leave the screen, and quitting (Ctrl-C or Quit) asks for the same key twice while firewalls are being changed. "Rehearse (dry run)" runs the same steps against a model. Behind it, `prepare` is now three phases in `cli` (`_prepare_review`, approval, `_prepare_execute`) that the command and the screen share.
- Sign-in screen: the accounts table has a **last sign-in test** column: "connected successfully on <date time>", "failed on <date time>" (the reason is shown under the table) or "not tested yet". The result is saved at once, in `sign_ins.json` in the profile's folder, so it is still there after the message has gone, after the screen is left and next time. Giving an account a new secret forgets its old result.
- Sign-in screen: the unclear "Profile in use is: remembered automatically" row is now "When none is named, use: the profile used last / always the profile above", with a sentence under it saying exactly what each choice does.
- Shell: **Choose firewalls** (Alt-F) now comes before **Fleet report** in the list of steps (Alt-1 to Alt-9 follow the new order).
- Shell: the last answer of the report and the plan is kept per profile, address and target and shown again, marked with how old it is, however often the screen is left and re-entered; Refresh keeps the old answer on show until the new one arrives. A read that finished while another screen was in front is collected at once (before, a finished read could sit uncollected, showing a blank body, until a key was pressed). A sign-in or certificate problem found while you were elsewhere waits for your next visit instead of pulling you away.
- Shell: **Jobs** (Alt-J, step 9) lists all background work, newest first, with what it is doing now or how it ended, and everything it printed; on a window 120 columns or wider the same list runs down the right-hand side of the other screens (170 for the sign-in and settings forms). Panorama calls report what they are asking ("asking Panorama: show devices all") through the new `progress` module. Two jobs at once no longer share one capture of the screen's output.
- Sign-in screen: Up and Down now follow what is drawn, top to bottom (profile, address, profile in use, accounts, action buttons, Save row). Before, the "Profile in use" row was walked between the action buttons and the Save row although it is drawn near the top, so Down from the buttons jumped up the screen. The action buttons that wrap onto several lines are walked line by line, keeping your place along the line.
- The test suite is pointed at a throwaway sign-in folder before anything runs, so a developer's own profiles are never written to.
- **Panorama profiles.** A site with several Panoramas keeps them apart: a profile is a workspace folder (`~/.panupgrade/profiles/<name>/`) holding one Panorama's address, its own admin accounts (a credentials file of its own, with the choice of which account reads and which changes), its firewall list, settings, release table and target version, and its run journals, upgrade kits and configuration backups. `panupgrade auth` makes and removes profiles and the accounts under them (removing renames the folder, never deletes). `--profile NAME` (or `PANUPGRADE_PROFILE`) picks one; a `--panorama` address picks the profile with that address; otherwise the one used last. The home screen of the shell has a profile row (Left / Right to switch); each profile remembers its own address and target. The upgrade script carries `--profile`.
- The sign-in settings file `auth.json` and the global account choice are gone: the choice of account lives in the profile. The environment variables `PANUPGRADE_CREDS`, `PANUPGRADE_ACCOUNT` and `PANUPGRADE_WORK_ACCOUNT` remain as overrides, and the user-level environment option on the sign-in screen now keeps the profile in use (`PANUPGRADE_PROFILE`).
- A Panorama whose certificate cannot be verified (a self-signed one, usually) no longer ends in a dead-end error. Adding an account with "sign in now", Test sign-in, and every step in the shell now show the reason and the certificate's SHA-256 fingerprint and ask **Accept risk & continue?**; on a plain terminal it is a `[y/N]` question. Accepting pins exactly that certificate for that address (`trusted_certs.json`), so later connections need the same certificate and a different one is refused. **Forget certificate** on the sign-in screen undoes it.
- `panupgrade` with no arguments (or `panupgrade shell`) opens one screen for the whole workflow: Panorama address and target version, then sign in, fleet report, choose firewalls, plan, prepare, upgrade, settings and the release table, each with its status and reachable with Alt-letters or Alt-1..8 from anywhere. Report and plan run in the background; a step that cannot sign in takes you to the sign-in screen and back. Prepare and upgrade show the command to run for now.
- Terminal layer: screens can poll background work, Alt hotkeys work on Windows and Unix terminals, and Ctrl-C now reaches every screen on Windows (before, it was ignored until another key was pressed).
- `cli` now has `build_parser`/`parse_args`; the select, settings and sign-in forms are built by functions the shell shares.
- New `panupgrade auth` screen: add, remove and test accounts in the credentials file (password, ready-made API key, or sign in once and keep only the key), choose which account reads and which makes changes, and keep that choice in `~/.panupgrade/auth.json` or in Windows user-level environment variables. A command that finds no credentials file or no usable account opens it on a terminal instead of stopping with an error. Environment variables still win over the settings file, and flags over both. The sign-in defaults are now read when needed instead of when the program starts.
- Removed `restore_roles = "pause"`. It stopped the whole run from starting any further firewall after the first pair and offered no way to make a decision, only to re-run with `--resume`. `restore_roles` is now `leave` or `restore`.
- Settings form: the explanation lists every choice a setting has, with what each means and the current one marked, so you do not have to change a value to read the others. PgUp / PgDn scroll the explanation when the window is too short to show it all, and the buttons always stay visible.
- Settings form: the explanation of the setting under the cursor now sits to the right of the list when the window is wide enough (below it otherwise); Up and Down wrap round the whole ring of settings and buttons in both directions; the `ha_config_unsynced` description is rewritten and broken into paragraphs.
- `sync_to_peer` is now `Disable`, `Both` (default) or `UpgradeOnly`. Both forces the passive member to match the active one in `prepare` and again during the upgrade, so an unsynced pair now needs acknowledgement (`force_config_sync`) in a plan instead of being refused; refusal applies only with `Disable`. Choices are matched without regard to case.
- `panorama_compare` is now `minor` (default) or `major` and is the unit for `spread_limit` (default 2) and for "Panorama older than the target". Minor distances are counted along a table of the PAN-OS releases that exist (there is no 12.0, so 11.2 is two behind 12.2). New command `panupgrade releases` shows the table; `--update` downloads the vendor's current list into `releases.json`, which commands in that folder then use; `--releases FILE` names another. The upgrade script pins the table it was prepared with.
- Settings form: all text wraps instead of being cut off with "...", and a long value is printed in full below the list.
- An account in the credentials file may now hold a ready-made API key (`'service': {'api_key': 'KEY'}`) instead of a password. `--key-file` is gone: an API key lives in the same credentials file as everything else, chosen with `--account` like any other.
- Removed leftovers from earlier designs, since there are no released versions to stay compatible with: the `PANUPGRADE_READ_ACCOUNT` variable, the `plan_credentials_file` and `apply_credentials_file` settings (and the `_file` exemption in the secrets check), and `--source panorama:ADDRESS` (use `--panorama ADDRESS`).
- `settings` opens a form on a terminal: every setting grouped on one screen with its default, a plain-words explanation of the setting and of its current value, live validation, and a caution for each risky setting. Save writes `settings.toml` (only values that differ from the defaults) and every command run from that folder uses it, saying so. Without a terminal, or with `--set`, it still prints the values.
- The terminal code shared by the `select` and `settings` forms moved to `tui.py`.
- `select` form: **Save**, **Save & Exit** and **Quit without saving** buttons at the bottom, with an "unsaved changes" marker. Ctrl-D and Esc remain as shortcuts.
- `select` form: a "Filters in effect" line lists every active filter, including ones hidden because the column was switched to another mode; more space before the Included table.
- The list `select` saves defaults to `upgradeList.txt`. `plan`, `prepare` and `upgrade` use it when no firewalls are named (`--all` ignores it), and the form reopens on it. Without the form, `select` only writes a file when given `--out`.
- `select` form: Shift-Tab now goes backwards on Windows (the console key event is read directly, since `msvcrt` cannot see Shift). The serial, model, HA, device group and tag filters match anywhere in the value, and `*` / `?` work in them, on the command line too (`--model "PA-8*"`).
- Device groups were never read from Panorama (`show devices all` does not carry them), so the device group column was always empty. They now come from `show devicegroups`; device tags are read from `show devices all`.
- `select` opens a form on a terminal: filters sit above the table columns (with modes such as pattern / contains and is / older than / newer than), and Available and Included tables let you build the exact batch. The equivalent flags are printed afterwards. `-i` / `--no-interactive` control it.
- The fleet report no longer counts the PAN-DB URL version against an HA pair; only app, threat and av content are judged (the standby usually cannot reach the URL cloud).
- Sign-in follows your setup: one account, separate read and change accounts, or a login typed at the prompt (`--ask-credentials changes|all`). No account names are assumed; a file with a single account needs no flag.
- Licensed under GPL-3.0-or-later.
- `--panorama ADDRESS` names the Panorama; `--source` takes only `fake:FILE`, the invented fleet. Commands now say which Panorama, credentials file (shown under ~ when in the home folder, with a warning when it is not), account and settings file they use.
- New `report` verb (fleet state, no target) and `help` verb (command overview); options grouped into connect, choose-firewalls and appearance.
- Plan output grouped by verdict (blocked first), routine skipped checks counted instead of listed (`--verbose` lists them), identical step lists shared.
- Credentials path and account names are configurable (`PANUPGRADE_CREDS`, `PANUPGRADE_ACCOUNT`, `PANUPGRADE_WORK_ACCOUNT`); upgrade kits pin them explicitly.
- Panorama TLS certificates are now verified by default; `--insecure-tls` / `PANUPGRADE_INSECURE_TLS=1` opts out with a warning.
- Safer defaults: `sync_to_peer = "prepare"`, `ha_config_unsynced = "block"`.
- Refused approvals say what changed; interrupted runs offer to continue or start fresh.
- Release-train minimum-content floors from the vendor release notes.
